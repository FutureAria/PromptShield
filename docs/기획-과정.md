# 기획 과정

기획서 한 장이 나오기까지 팀이 무엇을 정하고 어떤 순서로 일했는지 남긴다.
확정 사항은 Notion에서 관리했고, 이 문서는 그중 결정된 것만 옮긴 기록이다.

## 기획서 쪽별 구성

분량이 A4 5쪽으로 정해져 있어, 쓰기 전에 쪽마다 무엇을 담을지와 누가 쓸지를 먼저 확정했다.
쪽 배치는 편집 과정에서 조정될 수 있지만 최종 분량은 5쪽 이내로 유지한다는 것이 전제였다.

| 쪽 | 핵심 내용 | 담당 |
|---|---|---|
| 1쪽 | 문제 배경, 대상 사용자, 지역 중소기업의 어려움 | 박주영 |
| 2쪽 | 해결 방법과 시스템 처리 흐름 | 박주영, 전체 |
| 3쪽 | 민감정보 탐지, 내부 LLM, 보안정책·DB 기술 구성 | 김주빈, 이서연, 홍재창 |
| 4쪽 | 화면 구성, 역할 분담, 일정 | 지영빈, 박주영 |
| 5쪽 | 기대효과, 평가항목, 향후 계획 | 전체 |

## 제안서 평가 항목

실제 결과값이 아니라 개발 단계에서 측정할 항목으로 미리 정해 두었다.
무엇을 만들 것인가와 함께 무엇으로 잘 만들었는지 판정할 것인가를 같이 정하려는 의도였다.

- 개인정보 탐지 정밀도·재현율·F1-score
- 정상 정보 오탐률과 민감정보 미탐률
- 마스킹 후 민감정보 잔존 여부
- 보안등급별 라우팅 정확성
- 프롬프트 검사 처리시간
- 주요 시나리오 통과율

## 조사 과정에서 우리 주장을 뒤집은 것

조사가 기획서를 뒷받침하기만 한 것은 아니다. 초안의 서술이 사실과 다르다는 것을 조사가
먼저 밝혀낸 경우가 있었고, 그때는 조사 결과를 따랐다.

**"외부 LLM은 입력을 학습에 쓴다" — 사실이 아니었다.**
확인해 보니 주요 사업자 모두 유료 API·기업 계약에서는 기본적으로 학습에 쓰지 않는다고
공식 문서에 밝히고 있었다. 그래서 대비 축을 '외부 대 내부'가 아니라 **'회사가 통제하는
계정 대 직원 개인 계정'**으로 바꿨다. 회사가 기업 계약을 맺어도 직원이 자기 계정 창에
붙여넣는 것은 막지 못한다는 것이 이 게이트웨이의 존재 이유가 됐다.

**감사 로그 보존기간을 1년으로 적었는데 2년이 맞았다.**
「개인정보의 안전성 확보조치 기준」 제8조①은 기본 1년 이상이지만 고유식별정보를 처리하는
시스템은 2년 이상을 요구한다. PromptShield는 정의상 주민등록번호를 탐지하므로 이 단서에
해당한다.

**탐지 기술 자체는 차별점이 될 수 없었다.**
Microsoft Presidio가 한국 식별자 recognizer를 이미 내장하고 있고, LLM 게이트웨이에
가드레일로 붙이면 마스킹과 차단은 설정만으로 된다. "한국어 민감정보를 탐지한다"를
차별점으로 내세우면 무너진다. 남는 차별점을 다시 정의해 기획서 5쪽을 새로 썼다.
