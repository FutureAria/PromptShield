# 화면 구성과 검증 시나리오 (담당: 영빈)

## 4쪽 삽입분 — 화면 구성

### 화면 설계 원칙

- 차단이 아니라 대안을 같은 화면에 둔다. 직원이 개인 계정으로 옮기면 탐지·마스킹·감사 기록이 함께 사라지는데, 보안업체가 기업 고객의 브라우저 사용 기록을 분석한 결과 생성형 AI에 붙여넣는 행위의 82%가 회사가 관리하지 않는 계정에서 일어났다[영빈-2].
- 판정에 근거를 붙이고 개입 강도를 등급별로 다르게 둔다. 보안 판단 요구가 누적되면 체념과 결정 회피가 나타나므로[영빈-3] 일반은 무개입, 주의부터 인라인 표시로 구상한다.
- 관리자 화면을 새 유출 지점으로 만들지 않는다. 막아 둔 값이 감사 화면에 원문으로 쌓이면 관리자 계정 하나가 최대 유출 지점이 된다.

### 직원용 화면

작성·검사 → 검사 결과 → 마스킹 미리보기 → 승인 요청 → 응답의 다섯 패널을 한 작업 화면에 상태별로 붙인다. 각 패널에는 입력창과 [검사] 버튼, 등급 배지와 원문 하이라이트·[오탐 신고], 원문과 전송본 대조(`[이름1]` 형태의 번호 토큰), 승인 사유 한 줄과 대기·승인·반려 상태, 처리 경로 라벨을 둔다. 화면을 나누면 이동 자체가 학습 대상이 되는데, 정보보호 교육을 실시하는 기업이 전체의 32.7%에 그쳐[영빈-9] 대상 기업에 사용 교육을 전제하기 어렵다.

| 등급 | 화면 표현 | 사용자의 다음 행동(강조 / 보조) |
|---|---|---|
| 일반 | 중립색 배지, 경고 없음 | 그대로 전송 / 내부 LLM 사용 |
| 주의 | 노랑 배지 + "마스킹 N건", 구간 하이라이트 | 가리고 보내기 / 미리보기·수정 |
| 기밀 | 파랑 배지 + 자물쇠, "외부 미전송" 문구 | 사내 LLM 처리 / 수정 후 재검사 |
| 위험 | 빨강 배지 + 사유 한 줄, 전송 버튼 비활성 | 문제 구간 제거 후 재검사 / 승인 요청 |

배지는 색에 라벨·아이콘·건수를 병기한다. 색만으로 판정이 전달되면 안 되고, 등급이 오를수록 붉어지는 스케일에서는 기밀이 주의보다 나쁜 상태로 읽혀 사용자가 내부 LLM 경로를 피하기 때문이다. 반도체 부문에서 소스코드와 회의록을 그대로 입력한 사례가 허용 20일 만에 보고된 바 있어[영빈-1], 위험 등급에도 재검사와 승인 요청이라는 출구를 두어 막다른 화면을 만들지 않는다.

### 관리자 화면

관리자가 겸임이므로 하루 몇 분으로 유지되는 요약 구조로 구상한다. 정보보호 예산을 쓰는 기업이 54.8%에 그치고, 정보보호 업무를 수행하는 기업 중 정보보호 조직을 갖춘 곳도 35.3%라는 조사가 근거다[영빈-9]. 화면은 다섯으로 둔다.

- 현황 대시보드는 지표 요약보다 처리 대기 목록을 위에 두어 볼 것보다 할 것을 먼저 보인다.
- 승인 대기는 마스킹 요약과 탐지 유형·사유를 제시한다. 승인과 반려 두 갈래만 두면 관리자가 안전한 반려를 기본값으로 삼으므로, 마스킹본 전송을 뜻하는 조건부 승인을 함께 두고 반려 사유를 요청자 화면에 표시한다.
- 감사 로그는 시각과 요청자, 등급, 탐지 유형별 건수, 처리 경로까지만 보이고 원문은 표시하지 않는다. 접속기록의 보관·점검이 안전조치 의무이므로[영빈-7] 열람 행위도 기록 대상으로 두고, 원문 열람 권한은 보안정책 파트를 따른다.
- 정책·기업 사전은 비개발자가 표 입력과 파일 가져오기로 갱신하고, 저장 전 시험 검사로 영향 범위를 확인한다. 갱신이 개발자 작업에 묶이면 사전은 도입 시점에서 멈추고 미탐이 남는다.
- 사용자·권한은 직원·승인자·감사자 역할을 배정하며, 권한이 없으면 조작 요소를 노출하지 않는다.

## 5쪽 삽입분 — 검증 시나리오와 향후 계획

### 평가항목별 검증 방법

아래 기준은 전부 기획 단계의 목표이며 측정 결과가 아니다. 지표 산식과 데이터셋 구축은 주빈 파트, 정책 규칙은 재창 파트이고 여기서는 확인 절차만 정의한다.

| 평가항목 | 확인 방법 | 목표 기준(미측정) |
|---|---|---|
| 정밀도·재현율·F1 | 합성 더미 양성·음성 세트에 유형별 정답 라벨을 부여해 대조 | 탐지 유형별 합격선은 주빈 파트의 평가 계획을 따른다 |
| 오탐률·미탐률 | 오탐은 정상 업무 문장 세트, 미탐은 표기 변형 세트로 분리 측정 | 오탐 5% 이하, 위험 등급 미탐 1% 이하(미탐 피해가 커 비대칭) |
| 마스킹 후 잔존 | 전송본을 원본 토큰 목록과 대조하되 정규화 후 재검사와 부분 문자열 검사를 포함 | 비허용 잔존 0건, 한 건이라도 남으면 불합격 |
| 등급별 라우팅 정확성 | 등급이 확정된 더미 입력의 도달 경로를 로그로 대조 | 경로 일치 100%, 결정론적 규칙이므로 오차를 두지 않음 |
| 검사 처리시간 | LLM 응답을 뺀 검사 구간만 200·1,000·5,000자별 p50·p95 계측 | 시연 장비에서 단일 요청·CPU 기준 1,000자 p95 1초 이내(지연은 우회 유인) |
| 시나리오 통과율 | 아래 시나리오와 경계·예외 항목을 체크리스트로 기록 | 필수 시나리오 G-01~G-04 전건 통과, 경계·예외는 항목별 기록 |

### 주요 테스트 시나리오

입력은 전부 명백한 더미이며 실제 개인정보와 거래처 정보는 투입하지 않는다.

| ID | 입력(더미) | 기대 등급·처리 | 확인 포인트 |
|---|---|---|---|
| G-01 | 회의록 요약 양식 요청 | 일반 · 그대로 전달 | 불필요한 마스킹·차단이 없는가 |
| G-02 | 홍길동 010-0000-0000 hong@example.com 안내문 | 주의 · 마스킹 후 전달 | 전송본에 원문 값이 없으면서 의도가 유지되는가 |
| G-03 | ABC상사 X-100 단가 12,000원 견적 문구 | 기밀 · 내부 LLM 처리 | 외부 호출이 한 건도 없는가 |
| G-04 | 주민등록번호 형식 더미(YYMMDD-1XXXXXX 형태의 실재하지 않는 값) | 위험 · 차단, 승인 안내 | 승인 전 어떤 경로로도 나가지 않는가 |

G-04는 형식 패턴 일치만으로 위험 판정한다는 전제이며, 규칙이 생년월일과 성별코드 유효성까지 요구하는지는 주빈 파트와 확인한다. 고유식별정보를 최상위 등급에 두는 것은 민감정보 입력 금지를 핵심 수칙으로 제시한 국내 기관 권고와 일치하고[영빈-6], 마스킹 후 전달과 사용자 고지는 생성형 AI 민감정보 노출 항목의 완화책과 대응한다[영빈-4].

### 경계·예외 확인

오탐은 "주민등록등본 발급 절차"처럼 낱말만 겹치는 문장이 통과하는지 보고, 미탐은 구분자 삽입, 전각 문자, 자모 분리, 로마자 표기 세트를 따로 둔다. 미탐 상당수는 규칙이 아니라 정규화 전처리 누락에서 생기고 오탐은 우회를 부르므로 둘을 같은 비중으로 다루며, 발견된 사례는 회귀 세트에 추가한다. 암호화 PDF와 이미지 첨부처럼 판정 불가인 입력이 "일반"으로 통과하지 않는지, 기밀 요청이 내부 LLM 지연·중단 시 외부로 폴백하지 않는지, 카나리 문자열로 로그와 DB에 원문 잔존이 0건인지도 확인한다.

### 시연·실행 환경 계획

외부 API 연계 시 접근통제 체계를 갖추라는 안내서 권고[영빈-5]에 따라 검사 지점을 사내에 두고, 사내망 서버 한 대에서 Docker Compose로 다섯 컨테이너(화면, 게이트웨이, 백엔드, DB, 내부 LLM)를 단일 명령으로 기동하는 구성을 계획한다. 백엔드와 DB, 내부 LLM은 호스트에 포트를 공개하지 않고 화면도 게이트웨이 뒤에 두어 진입점을 하나로 좁히며, DB 자격증명과 게이트웨이 설정은 배포 시점에 환경변수로 주입하는 것을 전제로 둔다. 내부 LLM은 동시 실행 수와 컨텍스트 길이에 비례해 메모리를 쓰므로[영빈-8] 시연 장비는 소형 모델 하나와 낮은 동시성, 컨텍스트 상한으로 고정하고, 발표장 네트워크와 모델 로딩, CPU 추론 지연에 대비해 노트북 단독 실행과 더미 응답 모드를 준비한다. 시연은 더미 데이터로 G-01~G-04를 순서대로 보인 뒤, 관리자 화면의 조건부 승인·반려와 원문 칸 없는 감사 로그 추적을 마지막 두 단계로 둔다.

## 통합 시 전제

- 검사 결과로 판정 등급, 탐지 항목의 유형·위치, 마스킹 결과, 처리 경로, 요청 식별자가 화면에 전달된다고 가정한다(탐지 기준 주빈, 전달 구조 재창).
- 승인 권한 판정 기준과 승인·반려 이력 구조, 원문 열람 권한은 보안정책 파트에서 정의되며, 화면은 조작 요소의 노출 여부만 결정한다. 감사 로그는 원문과 탐지 값이 제외된 형태로 제공된다고 가정한다.
- 탐지 유형별 F1 목표치는 3쪽과 5쪽의 수치가 어긋나지 않도록 09-01 통합 전에 주빈 파트와 맞춘다. 개발 착수 순서와 파일럿 도입 방안은 5쪽 '향후 계획'의 전체 담당분과 겹치므로 이 원고에서 제외했다.
- 각주는 통합 시 재번호를 전제로 [영빈-n]으로 표기했다. 지면이 빠듯하면 URL을 떼고 서지사항만 남기며, 더 모자라면 [영빈-1]~[영빈-3]을 줄이고 국내 법령·기관 출처를 남긴다. 그다음은 경계·예외 문단과 이 절 순으로 덜어내되 표 두 개는 남긴다.
