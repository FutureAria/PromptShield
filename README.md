# PromptShield

직원이 생성형 AI에 입력하는 프롬프트와 평문 첨부를 외부 전송 전에 검사하고, 민감도 4등급(일반·주의·기밀·위험)에 따라 전송 경로를 제어하는 보안 게이트웨이 시연용 프로젝트입니다. 지역 중소기업이 낮은 운영 부담으로 사내 AI 입력을 통제하는 상황을 가정합니다.

## Docker Compose로 바로 실행

Docker 데몬을 실행한 뒤 저장소 루트에서 다음 한 줄을 실행합니다.

```bash
docker compose up
```

처음 실행은 프론트엔드 이미지를 빌드합니다. 소스 변경 뒤 강제로 다시 빌드하려면 `docker compose up --build`를 사용합니다. 기동하면 [http://localhost:8080](http://localhost:8080)으로 접속합니다. 호스트에 공개되는 포트는 게이트웨이의 `8080` 하나뿐입니다.

기본 구성은 다음 네 서비스를 기동합니다.

- `gateway`: Nginx 단일 진입점. `/`는 화면으로, `/api/`는 백엔드로 전달합니다.
- `frontend`: React 프로덕션 빌드. 호스트 포트를 열지 않습니다.
- `backend`: FastAPI 게이트웨이. 탐지·등급 판정·마스킹·승인·감사를 담당합니다.
- `db`: PostgreSQL 16. 정책·사전·승인·감사 로그를 저장합니다.

호스트 8080이 이미 쓰이고 있으면 `GATEWAY_PORT=8090 docker compose up` 으로 바꿉니다.

화면은 기동할 때 `/api/health` 를 한 번 확인합니다. 백엔드가 있으면 실제 게이트웨이를 쓰고, 없으면 목 API로 떨어져 그대로 시연할 수 있습니다. 그래서 백엔드를 빼고 프런트만 띄워도 화면 시연이 끊기지 않습니다.

### 향후 전체 프로필

`backend/`에 실제 소스와 Dockerfile이 생긴 뒤에는 다음 명령으로 백엔드·PostgreSQL·Ollama까지 기동합니다.

```bash
docker compose --profile full up --build
```

현재 `backend/`에는 소스와 Dockerfile이 없어 `full` 프로필의 백엔드 빌드는 실패하는 것이 예상됩니다. 또한 DB와 Ollama를 사용하는 코드가 아직 없고 Ollama 모델 다운로드는 수 GB를 소모할 수 있어 세 서비스를 `full` 프로필 뒤로 분리했습니다. DB 기본값은 [`.env.example`](./.env.example)을 참고하고 실제 값은 Git에서 제외되는 `.env`에 둡니다. `backend`, `db`, `ollama`는 호스트에 포트를 공개하지 않습니다.

## 발표 시연 대본

모든 예시는 명백한 더미이며 실제 개인정보를 입력하지 않습니다. 다음 순서를 권장합니다.

1. `emp-hong`(홍길동)으로 로그인합니다.
2. 직원 화면에서 G-01~G-04를 순서대로 검사합니다.
   - G-01: `회의록 요약 양식을 알려줘` → **일반**, 그대로 전송
   - G-02: `홍길동 010-0000-0000 hong@example.com 으로 안내문 보내줘` → **주의**, 마스킹 후 전송
   - G-03: `ABC상사 X-100 단가 12,000원 견적 문구 만들어줘` → **기밀**, 사내 LLM 처리 시연
   - G-04: `주민등록번호 000000-0000000 확인해줘` → **위험**, 전송 차단·승인 요청
3. 첨부를 시연합니다. 일반 평문 `.txt`, 기밀어 `ABC상사`가 든 `.csv`, 그리고 PDF 또는 이미지를 붙여 파일 바이트 기반 **판정 불가·위험** 차단을 확인합니다.
4. G-04에서 **관리자 승인 요청**을 누르고 로그아웃한 뒤 `sec-park`로 로그인합니다. `/admin/approvals`에서 **조건부 승인**하고, 다시 홍길동으로 로그인해 마스킹본을 전송합니다.
5. `sec-park`로 `/admin/dictionary`에 들어가 `X-100`을 제품코드·기밀로 추가합니다. 저장 전 시험 검사 → 저장 → 직원 화면 재검사로 사전이 실제 탐지에 반영됨을 보여 줍니다.
6. 마지막으로 `/admin/logs`에서 등급·처리 경로·탐지 건수와 승인자를 확인하고, 원문이 관리 경로에 노출되지 않음을 설명합니다.

## 새로고침 복구와 시연 초기화

검사 결과, 승인 상태·대기 목록, 감사 로그, 기업 사전, 계정·역할 변경 이력을 탭 단위 `sessionStorage`의 하나의 목 상태 키에 보존합니다. 발표 중 F5를 눌러도 시나리오를 이어 갈 수 있고 탭을 닫으면 사라집니다. 저장소가 막히거나 용량을 초과하면 기능을 중단하지 않고 메모리 상태로 계속 동작합니다. 2MB 저장 예산을 넘으면 가장 오래된 검사 결과부터 제외합니다.

시연을 처음부터 다시 시작하려면 `sec-park` 승인자로 `/admin`에서 **시연 데이터 초기화**를 누른 뒤 확인 단계에서 **초기화 실행**을 누릅니다. 초기화 권한은 승인자에게만 있으며 현재 로그인은 유지됩니다.

> **시연 전용 보안 절충:** 새로고침 복구를 위해 목 검사 원문과 결과도 `sessionStorage`에 들어갑니다. 같은 브라우저 탭 안에만 머물고 탭을 닫으면 사라지지만, 원문을 영속 저장소에 두지 않는 제품 원칙에 대한 의도적인 절충입니다. 실제 백엔드 연동 시에는 브라우저가 아닌 서버가 상태를 관리하고 보존·암호화·접근 정책을 적용해야 합니다.

## 오프라인 발표

빌드된 앱은 목 API와 한국어 시스템 폰트 폴백을 사용하며, 런타임에 CDN이나 기타 외부 네트워크가 전혀 필요하지 않습니다. 단, 발표장 이동 전에 Docker 이미지 빌드와 `docker compose up`을 한 번 검증하는 것을 권장합니다.

## 현재 한계

- Ollama 사내 LLM은 모델이 수 GB라 기본 구성에서 뺐습니다. `docker compose --profile llm up` 으로 함께 띄우고 모델을 한 번 받아야 실제로 답변합니다. 없으면 기밀 등급 요청에 "사내 LLM에 연결하지 못했다"는 안내가 표시되며, 그 요청이 외부로 나가지 않는다는 성질은 유지됩니다.
- 답변 재검사(외부 LLM 응답에 민감정보가 되돌아오는 경우)는 아직 구현하지 않았습니다.
- 한국어 개체명 인식(NER)과 문맥 분류는 조사 단계이며, 현재 탐지는 규칙과 기업 사전 기반입니다.
- PDF와 이미지, Office/HWP 문서의 내용은 검사하지 않습니다. 읽을 수 없는 첨부는 `판정 불가`로 표시하고 위험 등급으로 차단합니다.
- 프론트엔드 역할 가드는 시연 UX이지 보안 경계가 아닙니다. 실제 인증·권한 판정은 서버에서 강제해야 합니다.

## 개발 검증

```bash
cd frontend
npm ci
npx tsc --noEmit
npm run build
npm test

cd ../backend
python -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest tests/ -q    # 42개

cd ..
docker compose config
```

더 자세한 화면·첨부·승인 시나리오는 [`frontend/README.md`](./frontend/README.md)에 있습니다.
