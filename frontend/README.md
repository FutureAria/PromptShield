# PromptShield 프론트엔드

생성형 AI에 입력할 문장과 평문 첨부를 외부 전송 전에 검사하고, 민감도에 따라 그대로 전달·마스킹·사내 LLM 처리·차단 경로를 보여 주는 React 데모입니다. 백엔드 없이 목 API만으로 역할별 화면 접근, 직원·승인자 사이의 승인 왕복, 실제 탐지에 연결된 기업 사전과 역할 배정까지 재현합니다.

## 실행 방법

저장소 루트에서 Docker 데몬을 실행한 뒤 다음 한 줄로 프로덕션 빌드를 띄웁니다.

```bash
docker compose up
```

브라우저에서 [http://localhost:8080](http://localhost:8080)에 접속합니다. 기본 Compose 실행은 `frontend`와 `gateway`만 기동하고 호스트에는 게이트웨이의 `8080`만 공개합니다. 화면은 목 API로 자체 완결되므로 이 구성만으로 모든 시연이 동작합니다. 백엔드가 없는 동안 `/api/` 요청이 `502 Bad Gateway`를 반환하는 것은 정상이며, Docker DNS 지연 해석 덕분에 그 경우에도 Nginx와 화면은 정상 기동합니다.

현재 `backend/`에는 소스와 Dockerfile이 없고 DB·Ollama를 사용하는 코드도 없습니다. 특히 Ollama 모델은 수 GB를 내려받을 수 있어 `backend`, `db`, `ollama`를 `full` 프로필로 분리했습니다. 백엔드가 구현된 뒤 다음 명령으로 전체 구성을 기동합니다. 지금은 백엔드 빌드가 실패하는 것이 예상됩니다.

```bash
docker compose --profile full up --build
```

DB의 `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` 값은 루트 [`.env.example`](../.env.example)의 기본값을 복사해 `.env`에서 바꿀 수 있습니다. 세 `full` 서비스는 호스트 포트를 열지 않습니다.

로컬 개발에는 Node.js 20 이상과 npm이 필요합니다.

```bash
npm ci
npm run dev
```

개발 서버는 `http://localhost:3000`에서 실행됩니다.

처음 접속하면 `/login`에서 비밀번호 없이 데모 계정을 선택합니다. 이 화면은 역할별 동작을 시연하기 위한 계정 선택 화면이며, 실제 배포에서는 사내 계정 인증으로 대체해야 합니다.

```bash
npx tsc --noEmit  # strict TypeScript 검사
npm run build     # dist/ 프로덕션 빌드
npm test          # Vitest 시나리오 테스트
```

## 역할과 로그인

| 역할 | 값 | 접근 범위 | 기업 사전 | 사용자·권한 |
|---|---|---|---|---|
| 직원 | `employee` | 직원 화면(`/`) | 접근 불가 | 접근 불가 |
| 승인자 | `approver` | 직원 화면, 관리 현황, 승인 대기 처리, 감사 로그 조회 | 조회·편집 | 조회·역할 배정 |
| 감사자 | `auditor` | 직원 화면, 관리 현황, 감사 로그 조회 | 조회 전용 | 조회 전용 |

승인 대기 처리는 승인자만 할 수 있습니다. 직원에게는 관리자 링크를, 감사자에게는 승인 대기 메뉴를 표시하지 않으며 URL을 직접 입력해도 라우트 가드가 접근을 거부합니다. 로그인하지 않은 사용자가 보호된 주소에 접근하면 로그인 뒤 원래 주소로 돌아갑니다.

### 데모 계정

| 사용자 ID | 이름 | 부서 | 역할 | 설명 |
|---|---|---|---|---|
| `emp-hong` | 홍길동 | 영업팀 | 직원 | 업무 요청을 보내는 일반 직원 |
| `emp-kim` | 김철수 | 생산관리팀 | 직원 | 업무 요청을 보내는 일반 직원 |
| `sec-park` | 박보안 | 정보보안팀 | 승인자 | 위험 요청의 승인·반려와 시연 초기화를 처리한다 |
| `aud-lee` | 이감사 | 감사팀 | 감사자 | 감사 로그를 조회한다. 승인 처리는 할 수 없다 |

로그인 세션은 `sessionStorage`에 저장되어 같은 탭에서 새로고침해도 유지됩니다. 로그아웃하면 인증 세션을 삭제합니다.

> **보안 주의:** 프런트의 역할 검사와 라우트 가드는 사용자 편의를 위한 것이며 보안 경계가 아닙니다. 실제 백엔드 연동 시 세션은 서버가 발급하고, 권한 판정의 최종 책임도 서버에 있습니다.

## 화면

- `/login`: 데모 계정 선택
- `/`: 직원용 AI 채팅, 문서 첨부와 검사 결과 대조 화면(모든 역할)
- `/admin`: 관리자 대시보드(승인자·감사자)
- `/admin/logs`: 원문을 저장하거나 표시하지 않는 감사 로그(승인자·감사자)
- `/admin/approvals`: 승인·마스킹본 조건부 승인·반려 처리(승인자 전용)
- `/admin/dictionary`: 실제 직원 검사에 적용되는 기업 용어 사전과 저장 전 시험 검사(승인자 편집·감사자 조회)
- `/admin/users`: 데모 계정 역할 배정, 권한 매트릭스, 최근 역할 변경(승인자 편집·감사자 조회)

## 목 API 구조

- `src/api/types.ts`: 팀 공통 API 계약
- `src/api/permissions.ts`: 라우트 가드·메뉴·목 API·권한 매트릭스가 함께 읽는 능력 표
- `src/api/roleAssignment.ts`: 본인 변경과 마지막 승인자 강등을 막는 공통 역할 판정
- `src/api/dictionary.ts`: 기업 사전 저장소, 검증, 붙여넣기 파서와 오탐 감시 문장
- `src/api/attachments.ts`: 파일 바이트 판별, 평문 디코드, 본문과 첨부의 검사 입력 합성
- `src/api/mock.ts`: 정규식·기업 사전 탐지, 오프셋 기반 마스킹, 가짜 AI 응답, 감사 로그·승인 대기·역할 변경 데이터
- `src/api/index.ts`: 화면이 참조하는 API 진입점

검사·전송·승인·관리 화면용 함수는 Promise 기반으로 제공하며 실제 환경과 비슷하게 지연됩니다. 인증용으로 `listDemoAccounts`, `login`, `logout`, `getStoredSession`도 제공하며, `getStoredSession`만 `sessionStorage`를 즉시 읽는 동기 함수입니다. 테스트에서는 `setMockDelayRange`로 인위적 지연을 줄일 수 있습니다.

기업 사전은 `getDictionary`, `checkDictionaryDraft`, `previewInspection`, `saveDictionary`로 조회·검증·시험·저장합니다. 저장된 활성 항목은 곧바로 `inspect`가 읽으므로 화면 장식이 아니라 직원 검사 결과를 실제로 바꿉니다. 시험 검사의 입력과 결과는 검사 저장소나 감사 로그에 남지 않으며 `send`에도 사용할 수 없습니다. 사용자 화면은 `listUsers`, `assignRole`, `listRoleChanges`로 계정 역할과 최근 변경을 다룹니다.

위험 요청은 `requestApproval(requestId)`로 승인 건을 만들고, 직원 화면은 `getApprovalStatus(requestId)`를 3초마다 조회합니다. 관리자가 `decideApproval(approvalId, decision, reason?)`으로 승인하면 원문을, 조건부 승인하면 마스킹본을 전송할 수 있습니다. 반려하면 입력한 사유 전문을 직원 화면에서 확인할 수 있습니다. 관리자 화면과 감사 로그에는 원문을 저장하거나 전달하지 않습니다.

검사 결과, 승인 상태·대기 목록, 감사 로그, 기업 사전 스냅샷, 계정 목록과 역할 변경 이력은 `promptshield.mockState`라는 하나의 `sessionStorage` 키에 함께 보존됩니다. 따라서 같은 탭에서 새로고침해도 로그인과 시연 상태를 이어 갑니다. 저장소 읽기·쓰기는 모두 실패할 수 있는 것으로 보고 처리하므로 프라이빗 모드나 용량 초과에서도 기능은 메모리 상태로 계속 동작합니다. 직렬화 결과가 2MB를 넘으면 오래된 검사 결과부터 제외합니다.

`resetDemoState`는 이 목 상태를 씨앗 값으로 되돌리고 통합 저장 키를 지웁니다. `/admin`의 **시연 데이터 초기화** 조작은 `admin.demo.reset` 능력이 있는 승인자에게만 보이며, 별도 확인을 거친 뒤 실행합니다. 로그인 세션 키는 지우지 않으므로 초기화 뒤 대시보드 데이터를 즉시 다시 불러옵니다.

> **시연 전용 보안 절충:** 새로고침 복구를 위해 검사 원문과 결과도 탭 단위 `sessionStorage`에 기록합니다. 탭을 닫으면 사라지고 같은 브라우저 안에만 머물지만, 원문을 영속 저장소에 두지 않는 제품 원칙에 대한 의도적인 목 전용 절충입니다. 실제 백엔드 연동 시에는 브라우저가 아닌 서버가 상태를 관리하고 보존 기간·암호화·접근 정책을 적용해야 합니다.

## 문서 첨부

직원 화면의 **파일 첨부**는 실제 `input[type=file]`을 사용하며 여러 파일 선택과 키보드 조작을 지원합니다. 드래그앤드롭은 같은 첨부 경로를 부르는 보조 수단입니다. 본문과 읽힌 첨부는 `--- 첨부1 ---`처럼 파일 이름이 없는 순번 구분선으로 합쳐 한 번 검사하며, 본문과 모든 첨부에서 나온 탐지 중 가장 높은 민감도가 요청 전체의 등급과 처리 경로가 됩니다.

### 읽을 수 있는 형식

내용이 UTF-8(BOM 유무 무관) 또는 EUC-KR/CP949로 인코딩된 **평문**만 읽습니다. 파일 선택 창은 `.txt`, `.md`, `.csv`, `.tsv`, `.log`, `.json`, `.yaml`, `.yml`, `.xml`, `.sql`, `.ini`, `.conf`와 `text/plain`으로 범위를 좁히지만, 확장자와 MIME은 통과권이 아닙니다. 실제 판정은 언제나 파일 바이트로 합니다.

PDF(암호화 여부 무관), 이미지, docx·xlsx·pptx·hwpx 같은 ZIP 계열 문서, hwp·doc·xls 같은 OLE 문서, 압축 파일, 미디어와 실행 파일은 내용을 읽은 척하지 않습니다. UTF-16, UTF-8과 EUC-KR 어느 쪽으로도 온전히 읽히지 않는 입력, 바이너리로 보이는 입력, 읽기 실패와 20,000자 초과 문서도 **판정 불가**로 처리합니다. PDF의 확장자만 `.txt`로 바꿔도 PDF 매직 넘버를 찾아 실제 형식을 알립니다.

판정 불가는 별도 통과 등급이 아니라 `blocked` 심각도의 탐지 한 건입니다. 따라서 본문이 비었거나 일반이어도 요청 전체가 **위험**으로 올라가 전송이 차단되고 관리자 승인 경로만 열립니다. 승인되더라도 읽지 못한 파일의 바이트는 전송되지 않으며, 본문과 읽어낸 첨부만 처리됩니다. 필요한 내용은 파일에서 골라 평문으로 붙여넣은 뒤 다시 검사할 수 있습니다.

0바이트 파일은 읽기에 성공한 빈 파일이므로 검사 입력에 넣지 않고 등급에도 영향을 주지 않습니다.

### 첨부 상한

| 항목 | 상한 | 초과 시 처리 |
|---|---:|---|
| 파일 개수 | 3개 | 넘는 파일은 목록에 넣지 않음 |
| 파일 하나의 크기 | 1MB | 파일을 읽기 전에 거부 |
| 첨부 전체 크기 | 2MB | 합계를 넘기는 파일을 목록에 넣지 않음 |
| 파일 하나의 추출 텍스트 | 20,000자 | 붙인 파일을 판정 불가로 유지 |

개수와 바이트 크기는 파일 내용을 읽기 전에 알 수 있으므로 요청 목록 진입 전에 거부합니다. 형식·인코딩·텍스트 길이는 파일을 붙인 뒤에야 알 수 있으므로 해당 첨부를 판정 불가 카드로 남겨 사용자가 제거하거나 필요한 부분만 붙여넣을 수 있게 합니다.

### 파일 이름과 내용의 보존 범위

파일 이름은 첨부한 본인의 현재 카드와 전송·승인 요청 후 대화 이력의 첨부 칩에만 표시됩니다. 파일 이름을 검사 입력, 원문·전송본 대조, `ChatMessage.text`, 승인 대기나 감사 로그에 넣지 않습니다. 관리자에게는 파일 이름과 내용 대신 `판정 불가 n건`과 `[판독불가1]` 같은 마스킹 토큰만 전달되며, 승인 미리보기는 앞 500자로 제한됩니다.

전송이 성공하면 현재 첨부 목록을 비워 같은 파일이 다음 요청에 다시 붙는 일을 막습니다. 파일 이름과 원본 바이트는 `sessionStorage`에 기록하지 않습니다. 다만 새로고침 복구를 위한 목 검사 결과의 원문에는 읽어 낸 평문 첨부 텍스트가 포함될 수 있습니다. 이는 위의 시연 전용 절충에 해당하며, 판독하지 못한 PDF·이미지 바이트는 저장하지 않습니다.

## 실제 백엔드로 교체하기

1. `src/api/types.ts` 계약을 사용하는 `src/api/real.ts`를 만들고 같은 공개 API를 서버 호출로 구현합니다. 세션은 서버가 발급하도록 데모 계정 선택을 사내 인증으로 교체합니다.
2. 검사 결과의 `start`와 `end`는 JavaScript 문자열 오프셋 기준으로 전달합니다. `end`는 해당 구간 다음 위치입니다.
3. `src/api/index.ts`의 export 대상을 `./mock`에서 `./real`로 바꿉니다. 화면 코드는 API 진입점만 참조하므로 수정할 필요가 없습니다.
4. 감사 로그 응답에는 원문이나 실제 탐지 값을 추가하지 않습니다. 유형별 건수만 전달합니다.

## 시연 입력

권장 전체 순서는 **로그인 → G-01~G-04 → 첨부(판정 불가 포함) → 승인 왕복 → 기업 사전 → 감사 로그**입니다. 시작 전 씨앗 상태가 필요하면 `sec-park`로 `/admin`의 **시연 데이터 초기화**를 확인 후 실행합니다.

| 시나리오 | 입력 | 기대 결과 |
|---|---|---|
| G-01 정상 전송 | `회의록 요약 양식을 알려줘` | 일반 · 그대로 전송 |
| G-02 마스킹 후 전송 | `홍길동 010-0000-0000 hong@example.com 으로 안내문 보내줘` | 주의 · 이름/전화/이메일을 가린 뒤 전송 |
| G-03 내부 LLM 처리 | `ABC상사 X-100 단가 12,000원 견적 문구 만들어줘` | 기밀 · 외부 전송 없이 사내 LLM 처리 |
| G-04 전송 차단 | `주민등록번호 000000-0000000 확인해줘` | 위험 · 전송 차단 또는 관리자 승인 요청 |

모든 입력은 시연을 위한 명백한 더미이며 실제 개인정보를 넣지 않습니다.

### 문서 첨부 시연

아래 순서로 직원 화면의 본문과 첨부가 한 요청으로 판정되는지 확인할 수 있습니다. 시연 파일에도 실제 개인정보를 넣지 않습니다.

1. 민감정보가 없는 UTF-8 `.txt`를 본문 없이 첨부해 검사합니다. **일반 · 그대로 전송**이 나오고 전송 뒤 현재 첨부 목록이 비워집니다.
2. `주민등록번호 000000-0000000 확인해줘`가 든 `.txt`를 첨부합니다. **위험 · 전송 차단**과 **관리자 승인 요청** 경로가 나옵니다.
3. `거래처,요청\nABC상사,견적 작성`이 든 UTF-8 `.csv`를 첨부합니다. 기업 사전의 거래처명이 탐지되어 **기밀 · 사내 LLM** 경로가 나옵니다.
4. PDF 또는 PNG·JPEG 이미지를 첨부합니다. 내용 추출을 흉내 내지 않고 **판정 불가 · 위험**으로 차단합니다.
5. PDF 파일의 확장자만 `.txt`로 바꿔 첨부합니다. `확장자는 .txt인데 실제 내용은 PDF다`라는 위장 형식 안내와 **위험** 등급을 확인합니다.
6. 본문에는 `회의록 요약 양식을 알려줘`를 쓰고, `ABC상사 견적을 정리해줘`가 든 `.txt`를 첨부합니다. 본문은 일반이지만 첨부가 기밀이므로 요청 전체가 **기밀 · 사내 LLM**으로 올라갑니다.

### 승인 왕복 시연

1. 홍길동 또는 김철수 계정으로 로그인하고 직원 화면(`/`)에서 `주민등록번호 000000-0000000 확인해줘`를 검사합니다.
2. **관리자 승인 요청**을 눌러 대기 상태와 대화 이력의 요청 흔적을 확인합니다.
3. 로그아웃한 뒤 박보안 계정으로 로그인합니다. 승인 화면(`/admin/approvals`)에서 방금 요청을 **조건부 승인 — 마스킹본 전송**으로 처리합니다. 필요하면 전환 전에 새로고침해도 요청 상태가 유지됩니다.
4. 다시 로그아웃하고 최초 직원 계정으로 로그인해 조건부 승인 결과를 확인합니다.
5. **마스킹본 전송**을 눌러 실제 처리 경로가 `마스킹 후 전달`로 기록되는지 확인합니다.

### 기업 사전 왕복 시연

1. 박보안 계정으로 로그인하고 기업 사전(`/admin/dictionary`)에서 `X-100`을 제품코드·기밀로 추가합니다.
2. `X-100 견적 만들어줘`를 저장 전 시험 검사해 저장본과 초안의 차이, 새로 잡는 항목과 처리 등급을 확인합니다. 시험 문장에는 실제 민감정보를 넣지 않습니다.
3. **저장**을 눌러 `지금부터 직원 화면 검사에 반영된다`는 완료 안내를 확인합니다.
4. 로그아웃한 뒤 홍길동 계정으로 로그인하고 직원 화면(`/`)에서 같은 문장을 검사합니다. 제품코드가 탐지되고 기밀·사내 LLM 경로가 선택됩니다.
5. 이감사 계정으로 다시 로그인해 기업 사전과 사용자·권한 화면은 보이지만 저장·행 추가·역할 변경 조작은 보이지 않는지 확인합니다.

### 감사 로그 마무리

박보안 또는 이감사 계정으로 `/admin/logs`를 열어 앞선 검사와 승인 처리의 등급, 처리 경로, 유형별 탐지 건수와 승인자를 확인합니다. 검색·등급·기간 필터를 사용하고, 관리 화면에는 프롬프트 원문이나 실제 탐지 값이 나타나지 않는다는 점을 설명합니다.

## 오프라인과 알려진 한계

프로덕션 빌드는 목 API와 한국어 시스템 폰트 폴백을 포함하며 런타임에 CDN이나 그 밖의 외부 네트워크가 전혀 필요하지 않습니다.

- FastAPI 백엔드, PostgreSQL DB, Ollama 내부 LLM은 아직 구현되지 않았습니다. 현재 응답·승인·감사 흐름은 목 API입니다.
- PDF·이미지와 Office/HWP 문서의 내용을 검사하지 않습니다. 읽지 못한 첨부는 통과시키지 않고 **판정 불가·위험**으로 차단합니다.
- 목 상태 원문을 탭 단위 `sessionStorage`에 두는 것은 새로고침에 견디기 위한 시연 전용 절충이며 실제 저장 설계가 아닙니다.
